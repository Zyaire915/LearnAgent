# 外部资料质量审查
## 当前实现：正文审核（R7）

本节取代下方历史版本对“当前行为”的描述。保留 R5 搜索策略，不恢复已撤回的 AI 查询改写。

- 搜索及历史/来源去重后，最多选 10 个候选，一次 Tavily Extract advanced 批量抓取页面正文，不发送 query/chunks_per_source，避免只得到查询相关片段。API 文档：https://docs.tavily.com/documentation/api-reference/endpoint/extract 。
- 使用已有 ChatClient 对每份抓取内容审核相关性、教学实质、明显知识错误、推广、乱码和目录/登录页。要求给出实际连续原文引文；程序验证引文存在后才接受。此为 AI 对抓取内容的质量评估，不等于逐条事实外部交叉验证，也不保证抓取服务完整还原原网页。
- 作者、发布机构、首次发布日期从抓取内容提取，附带原文证据，不使用搜索响应的作者/日期作为最终结果的回退。署名不是身份认证；未抓到字段保持未知，不因未知扣分。日期拒绝未来值，要求来源引文含对应年月日；目前文本月份等未满足数字校验的日期保守保留未知。
- 正文不足 200 或超过 24000 字符、提取失败、模型缺失/失败、拒绝或引文校验失败均不进入推荐；不截断长文后宣称已完整阅读。当前长文/PDF/无字幕视频可能无法入选，是明确限制，后续可增加分段审核。
- 每次最多一次 Extract、10 次逻辑模型审核调用（模型客户端自身重试策略仍有效），最多推荐 5 条；不够则少推荐。Extract 服务超时参数20秒、HTTP连接10秒/读取30秒。新增调用增加费用与耗时，模型调用采用现有 ChatClient 的超时/重试配置。
- 新记录状态 BODY_REVIEWED，页面显示“正文AI审核”，依据保存正文引文、抓取时间、原文作者/机构/日期；数据库沿用现有 review_reason 等字段，不改已执行的 V11。再次排序保留正文证据。
- 可访问性和互动量均不再评分，新规则最高 88（35+40+8+5），并非百分制。兼容字段保留但不使用。旧资料不重算；前端卡片隐藏旧两项说明并明确旧分数保留，原始 Markdown 历史文件保持原样。
- 日志仅记录候选数、提取数、通过数或服务不可用，不输出密钥、正文或模型异常细节。审核失败不回退为搜索摘要推荐。

验证使用模拟 HTTP/模型，不访问真实 API、读取密钥或运行数据库集成；真实效果需重启服务后重新生成推荐验收。下文均为演进历史，涉及 R2–R6 的评分与限制不代表 R7。

## 处理链路

Tavily 每批获取最多 10 条候选，通过最多 4 批检索补充官方和公开课程来源，先过滤用户隐藏的域名，再评分、排除历史、去重并截取调用方需要的数量。每日推荐、项目研究和 Agent 搜索复用该入口。每日推荐与项目研究保存分数、来源级别、审查状态、推荐依据；外部资料列表按质量分展示，历史记录保持 `UNREVIEWED`，不冒充已经审查。

审查是可解释的规则评估，不代表人工认证。页面显示“推荐排序分”，用于同一主题下的相对排序，不是百分制或可信度百分比。当前已按用户要求回退到 R5 规则（R6 实验已撤回），最高 98 分（35 + 40 + 8 + 5 + 5 + 5）、可以为负数。不同主题或不同规则版本的分数不宜直接比较。

来源名单、权重、时间窗口、推广线索和审慎阈值集中在 `ResourceReviewPolicy.java`；相关性计算在 `ResourceRelevance.java`。新结果的理由以“规则 R5”开头；前端隐藏内部版本号，显示“程序自动审核”，加减分可展开查看。版本直接沿用现有理由字段保存，不修改已执行的 V11。旧资料保留原始分数和理由，不自动重算、不把旧理由换成新规则说明。

| 因素 | 规则 |
| --- | --- |
| 域名信誉 | 明确的官方、高校来源名单 +35；开放教育平台 +24；知名社区 +12；未匹配名单不加分，不据此断言不可信 |
| 主题相关性 | 每个查询词命中标题按 40 权重计算，只命中摘要按 10 权重计算；按查询词总数取整，合计最高 +40；标题和摘要均不匹配 -30，标为谨慎参考；无有效查询词时不加减分 |
| 作者/机构 | 提供方返回非空信息 +8，并注明身份未核实；未返回、空白信息保持未知，不加减分，不认定为原文无作者 |
| 发布日期 | 一年内 +5，三年内 +2，超过三年 +0；未返回、格式无法解析、晚于当前时间分别解释，不加分；可解析日期仍未核实原页面 |
| 可访问性 | 提供方明确报告可访问 +5，不可访问 -25；未知不加分 |
| 互动指标 | 仅对提供方返回的非负数据进行对数加分，最多 +5；缺失不加分，负数标记为异常且不加分 |
| 推广/转载/采集特征 | 明确促销短语、商业推广、段首转载/采集声明等线索 -30，并提示人工复核；不再仅凭“广告”“采集”“转载”三个话题词扣分 |
| 重复内容 | 规范化 URL（忽略跟踪参数及片段）去重；相同长摘要保留最高分候选；每日推荐还排除历史链接及高度相似的长摘要 |

同分时按 URL 排序，缺失互动量仍有稳定结果。白名单使用完整主机名或子域名边界匹配，`docs.oracle.com.evil.example` 不会被认定为官方。只接受无用户信息的 HTTP(S) URL。

规则入口：`ResourceQualityReviewer.java`。名单覆盖中国及海外的官方技术文档、高校、开放教育平台，集中维护在 `ResourceReviewPolicy.java`。仅匹配名单域名边界，不再为所有 `.edu` / `.edu.cn` / `.ac.uk` 域名自动加分。高校名单只是来源信号，不能保证其每个子页面都是课程。名单为初始维护目录，本轮未联网逐一验证网站当前可用性。社区知名度不意味着每篇文章可信。推广短语仍可能出现在技术示例中，规则仅提供线索，不能代替人工判断。

英文按完整词匹配，Java 不匹配 JavaScript；中英文连续书写先拆分（例如 Java集合），中文使用双字片段，单字词保留。忽略常见英文功能词并统一大小写、全半角。摘要只补充标题未命中的查询词，不重复加分。当前是词面匹配，不支持完整的跨语言语义理解；官方/课程定向检索也按原始学习主题评分，附加的检索词不参与加分。中文主题与纯英文资料可能因词面匹配不足而漏选，尚未增加自动翻译。

## 元数据与限制

Tavily 标准搜索结果不保证返回作者、机构、可访问性或互动量；适配器仅在响应实际带有对应可选字段时使用。缺失值保持未知，不从平台名称、摘要或模型推断点击量。当前没有额外调用视频平台 API，也没有逐条发起 HTTP 可访问性探测；页面会明确显示“可访问性未验证”。抓取时间记录本次搜索结果入库时间，并非原网站的抓取时间。

日期支持 ISO 时间、ISO 日期和 RFC 1123。适配器记录“非空日期无法解析”的信号，避免与缺失日期混淆。`AUTO_REVIEWED` 表示自动评估而非认证；低分、主题不匹配、有推广线索或提供方报告不可访问的结果标记 `CAUTION`。旧数据不回填推测分数。

第一阶段尚未访问原网页，因而不能确认原文确实没有署名，也不施加“已核实无作者”的扣分。原网页提取、身份核实、可访问性主动检测和平台互动数据采集均未新增。

## 隐藏与恢复

- `PUT /api/external-resources/{id}/hide-source`：从真实资源 URL 提取主机名并持久保存。
- `GET /api/external-resources/hidden-sources`：查看隐藏列表。
- `DELETE /api/external-resources/hidden-sources/{host}`：恢复来源。

隐藏按规范化主机名精确匹配（小写，去掉 `www.`），不连带隐藏其他子域名。它影响后续搜索、外部资料列表/资料集、每日摘要资源接口。外部资料页面提供隐藏和恢复按钮。含隐藏来源的资料集不预览旧 Markdown，工作台仍保留原始笔记，不删除用户已有文件。当前项目只有单演示用户，因此设置是全局的；引入多用户时需要增加用户隔离。

## 真实反馈后的质量门槛修订（R4）

用户反馈中出现 Solaris 发布说明、Python 文档目录及高校 PDF 乱码。R3 只要有少量关键词命中就可能靠域名分数入选；原清洗器没有识别乱码。R4 在保留分数计算的同时新增独立的入选门槛：标题覆盖至少 30% 的查询词，标题与摘要合计覆盖至少 40%；未达门槛标为 CAUTION 并排除，来源加分不能抵消。主题词仍按英文完整词与中文双字片段计算，是词面证据门槛，不是语义相关概率。较长、分散的查询及跨语言同义表达可能漏选，宁可不足 5 条也不靠域名凑数。

评分前在原始文本上检查多个 Unicode 替换字符、控制字符，以及大量拉丁扩展字母与希腊/西里尔字母异常混杂；摘要出现至少两段连续目录引导符时，作为抽取证据不足排除。不禁止 PDF 格式本身，不推测乱码原文；这只能识别部分明显损坏，不能保证识别所有编码错误。清理后的文本用于关键词匹配、展示及去重，移除行首 spContent=。正常法语重音与数学符号回归案例保留。

修订仅作用于新生成资料；不删除、改写数据库中的旧推荐或用户文件。本轮使用截图摘录和模拟候选验证，未请求真实 API、读取密钥或重启服务。

R4 验证：后端 62 项测试中 61 项通过、1 项数据库集成测试跳过，零失败。新增截图回归案例确认：网络主题下排除 Solaris/Python 目录与乱码，保留相关高校 PDF 和 MOOC；可信域名无法抵消弱相关。未修改前端，本轮未重复前端构建。

## 多主题、缩写与来源多样性修订（R5）

原因：旧搜索将完整查询重复发送，未分主题召回；旧评分虽然拆词，却用全部主题词作为统一分母，导致单主题课程被低估。ALU/CPU 缺少中英文别名，且“计算机”“工作原理”“详解”等上下文稀释核心词。R4 的相关性门槛放大了漏选。旧摘要去重阈值 0.85 主要识别近乎复制，且没有同站点数量约束。以上是代码与离线案例确认的机制，不代表已取得用户那几次真实搜索的原始响应。

- ResourceQuery 按明确列表标点拆分主题，列表中的“及/以及”也拆分，最多 12 个子主题。按最匹配的子主题评分及判断门槛，一条资料无需覆盖全部主题；选择时优先补充未覆盖的子主题。普通空格关键词仍作为同一主题，不把 Java collections List Map Set 任意拆成独立任务。
- 多主题检索：原始查询一次，加最多三组子主题查询。六主题示例分为“线性表 树”“图 查找”“排序 算法分析”。保持最多 4 次请求；为覆盖子主题，不再给每个主题额外执行官方和课程域名限制查询。来源评分仍有效。单主题保持原有普通/官方/课程/不足补搜流程。
- 显式归一化 ALU / 算术逻辑单元 / Arithmetic Logic Unit，以及 CPU / 中央处理器 / Central Processing Unit；这些查询移除泛化上下文“计算机”“工作原理”“详解”，并在搜索请求补充中英文称谓。仅覆盖已列出的别名，不宣称完整跨语言语义理解。
