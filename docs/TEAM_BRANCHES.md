# 小组功能分支与验收标准

所有分支都从公开基线 `main` 创建。先提交代码，再通过 Pull Request 合并；不要相互复制提交，也不要直接合并数据库 migration 文件。

## 1. `feature/resource-categories`：外部资料分栏

目标：把外部资料清晰分为“课程资料”“每日推荐”“学习项目”三个来源视图。

- 后端返回稳定的 `contextType` 与关联对象信息；使用 Flyway `V10`（确有数据库变更时）。
- 前端提供三个分栏、数量、空状态和来源链接。
- 已有记录要能根据课程、每日摘要或工作区上下文正确归类。
- 不改变搜索质量评分规则，避免与资源审查分支产生冲突。

验收：三类资料可以独立查看，刷新页面后分类不丢失，旧数据有明确兼容行为。

## 2. `feature/task-levels`：学习任务分级

目标：在现有优先级基础上增加用户易懂的任务层级与筛选方式。

- 优先复用现有 `TaskPriority`，如需扩展字段使用 Flyway `V12`。
- UI 至少支持“重要紧急 / 重要不紧急 / 普通”或经组内确认的三级语义。
- 创建、编辑、Agent 自动创建、筛选、排序和周报统计保持一致。

验收：任务可设置、修改、筛选和排序；旧任务有默认层级；Agent 创建任务不会报错。

## 3. `feature/module-history`：切换功能后保留内容

目标：用户从测试等页面切换到其他功能再返回时，仍能继续之前的上下文。

- 优先恢复后端已有会话/记录，前端仅保存当前记录 ID、筛选条件和未提交草稿。
- Quiz 保存当前课程、主题、题目、作答进度和结果入口。
- 页面刷新与路由切换都要验证；不得把 API Key 或完整敏感资料写入 `localStorage`。

验收：生成测试后切换页面并返回，题目和作答进度仍存在；后端重启后已提交记录仍可查看。

## 4. `feature/chat-history`：AI 对话历史

目标：对话能够创建、命名、继续和删除，切换课程或页面不会丢失。

- 数据库变更统一使用 Flyway `V9`。
- 保存会话、消息角色、课程、时间和必要的工具执行摘要。
- 前端提供历史会话列表、新建会话和继续对话。
- 不保存 API Key；工具输出过大时只保存结构化摘要。

验收：至少两段会话可相互切换；刷新和后端重启后仍可恢复；删除行为有确认提示。

## 5. `feature/resource-review`：外部资料质量审查

目标：减少低质量来源，优先可信、知名且与学习目标匹配的内容。

- 数据库变更统一使用 Flyway `V11`。
- 建立来源白名单/分级：官方文档与高校课程优先，其次是高质量 YouTube、Bilibili、CSDN、知乎等社区内容。
- 排名必须综合域名信誉、作者/机构、标题相关性、发布日期、可访问性和平台可获得的互动指标。
- 点击量只能作为加分项，不得伪造平台未返回的数据；软文、采集站、重复内容和无作者内容降权。
- 每条推荐展示来源、推荐理由、抓取时间和审查状态，用户可隐藏不可靠来源。

验收：同一主题的高质量官方或知名来源优先；低质量域名被降权；无互动数据时仍能稳定排序。

## 6. `feature/windows-launcher`：Windows 一键启动与可移植交付

目标：为普通用户提供一个入口，检查依赖、启动数据库/后端/前端并打开浏览器。

- 首版采用小型 Windows 启动器封装现有 PowerShell 脚本，不把 API Key 编译进 EXE。
- 支持“开发模式”和“演示模式”；端口占用、数据库未启动、Java/Node 缺失时给出中文提示。
- 所有可下载运行时、缓存和数据默认位于用户选择的目录，当前演示机继续使用 `D:\LearnAgent`。
- 面向其他电脑的发布包应包含构建后的前端与后端 JAR；数据库采用 Docker/Podman 或内置 PostgreSQL 二选一并写清前置条件。

验收：全新 Windows 用户按 README 操作后可一键启动；重复点击不会启动多份进程；退出时不删除用户数据。

## 合并顺序

推荐顺序：`chat-history` → `module-history` → `task-levels` → `resource-categories` → `resource-review` → `windows-launcher`。后一个分支在提 PR 前应合并或 rebase 最新 `main`，并解决测试与 migration 冲突。
